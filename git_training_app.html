🤔 Gitって何？

ファイルの「変更履歴」を全て記録してくれるタイムマシンのようなツールです。「いつ・誰が・どこを変更したか」が全てわかり、間違えてもいつでも過去の状態に戻せます。

🌐 GitHubとGitLabの違い

どちらも「Gitのデータをサーバー上で共有するサービス」ですが、用途が異なります。

  • GitHub：世界で一番有名。主にインターネット上のクラウドで使います。
  • GitLab：会社のネットワーク内（イントラ）に設置して「社内専用のGitHub」として使えます。ソースコードを社外に出せない企業で多く採用されています。

💡 GitLabでは「プルリクエスト」のことを「マージリクエスト（MR）」と呼びます。機能は同じです。

📖 必須の基本用語 7選

  1. リポジトリ：ファイルや変更履歴を保存しておく「金庫」
  2. クローン (clone)：サーバーの金庫を自分のPCに丸ごとコピー（参加初日に1回だけ）
  3. コミット (commit)：変更を記録して「セーブポイント」を作ること
  4. プッシュ (push)：PCのセーブデータをサーバーへアップロード
  5. プル (pull)：サーバーの最新データをPCにダウンロード
  6. ブランチ (branch)：メインの歴史から枝分かれした「自分専用の作業空間」
  7. マージリクエスト (MR)：「メインに合流させていいですか？」とチームに申請すること

環境構築（インストールと初期設定）
プロキシ環境対応。一度やれば二度とやらなくてOK！

🖥️ Gitのインストール

  1. 共有フォルダの Git for Windows インストーラーを実行する
  2. デフォルト設定のまま「Next」→「Install」でOK
  3. インストール後、スタートメニューから 「Git Bash」 を開く

⚙️ 初期設定（必須）

誰がコミットした履歴か分かるように名前とメールアドレスを設定します。

git config --global user.name "あなたの名前（例: Taro Yamada）"
git config --global user.email "社内のメールアドレス"

🔌 プロキシ設定（社内ネットワーク経由の場合のみ）

# 社内プロキシが必要な環境のみ実行してください
git config --global http.proxy http://社内プロキシのURL:ポート番号
git config --global https.proxy http://社内プロキシのURL:ポート番号

💡 設定が正しいか確認するには git config --list を実行すると全設定が表示されます。

新規プロジェクトの立ち上げ
git init + GitLab連携。「ゼロから始める」パターン

📁 既存フォルダをGitリポジトリにする

# プロジェクトフォルダに移動
cd C:\Users\自分の名前\Documents\my_project

# このフォルダをGit管理下に置く（1回だけ実行）
git init

# Gitが管理を開始したか確認
git status

🔗 GitLabのリポジトリと接続する

  1. ブラウザでGitLabを開き「New Project」→「Create blank project」を作成する
  2. 「Initialize repository with a README」のチェックは外す（理由は下記）
  3. 作成後に表示されるURLをコピーする
# GitLabのリポジトリと接続（URLは自分のものに変えること）
git remote add origin http://gitlab.your-company.local/yamada/my_project.git

# メインブランチ名をmainに統一
git branch -M main

# 初回プッシュ（-uをつけると次回から git push だけでOKになる）
git push -u origin main

⚠️ GitLabで「Initialize with README」にチェックを入れると、リモートに最初のコミットが生まれます。ローカルと歴史がズレてpushが失敗するので注意！

チーム開発（ブランチ & マージリクエスト）
本番では必ず使う！mainを守る作業の流れ

🌿 なぜブランチを使うの？

メインの歴史（main）に直接プッシュすると、自分のミスがチーム全員に影響します。ブランチを作って作業し、チェックしてもらってから合流（マージ）させるのが基本です。

💻 ハンズオン：ブランチ → 修正 → マージリクエスト
  1. ブランチを作って移動する
# feature_自分の名前 というブランチを作って移動
git checkout -b feature_yamada
  1. ファイルの内容を修正して保存・送信する
git add .
git commit -m "自己紹介を更新"
git push -u origin feature_yamada
  1. ブラウザでGitLabを開き「Create merge request」をクリックしてMRを作成する
  2. 隣の人とペアになり、お互いのMRを確認してApprove・Mergeする

⚠️ git push -u origin ブランチ名 の -u は最初だけ必要です。2回目以降は git push だけでOK。

毎日のルーティン（pull / commit / push）
朝と夜の2ステップを体に染み込ませよう

🌞 朝イチのコマンド（pull）

昨日、チームの他の人が加えた変更を自分のPCに取り込みます。これを怠ると後で歴史がズレてコンフリクトが発生します。

# 最新の状態をサーバーから取り込む（必ず朝イチに実行）
git pull origin main

🌛 帰宅前のコマンド（add / commit / push）

今日やった作業をGitLabに保存して帰ります。キリが良くなくても大丈夫。途中でも保存しておけばPCが壊れても安心です。

# 全変更をカートに入れる
git add .
# 今日の作業内容をセーブ（メッセージは具体的に！）
git commit -m "〇〇画面のバリデーション修正（途中）"
# GitLabへ送信して帰る
git push
💻 ハンズオン：朝のpullを体験する

隣の人がマージしたMRが自分のPCに取り込めるか確認しましょう。

# mainブランチに移動（作業ブランチにいる場合）
git checkout main
# 最新状態を取り込む
git pull origin main
# フォルダの中に隣の人のファイルが追加されていれば成功！

朝のpullを忘れると、チームの他の人の変更と自分の変更が衝突し、後で解決が大変になる可能性がある。

複数案件の管理（プロジェクトの切り替え）
A案件もB案件も、実は超シンプルに管理できる

📂 基本の考え方：案件 = フォルダ

案件ごとにフォルダを分けてクローンするだけです。それぞれのフォルダは完全に独立しています。A案件の変更がB案件に混ざることは絶対にありません。

💻 ハンズオン：2つの案件フォルダを作る
# まとめて管理するフォルダに移動
cd C:\Users\自分の名前\Documents\projects

# A案件をクローン
git clone http://gitlab.../project_A.git

# B案件をクローン
git clone http://gitlab.../project_B.git

# これでprojectsフォルダの中身は：
# projects/
#   ├── project_A/  ← A案件の独立した金庫
#   └── project_B/  ← B案件の独立した金庫

🔄 プロジェクトの切り替え方

  • VS Code を使う場合：「ファイル」→「フォルダーを開く」で切り替えるだけ
  • ターミナルを使う場合：cd project_A または cd project_B でフォルダを移動するだけ

⚠️ 必ずターミナルで正しいフォルダにいることを確認してからGitコマンドを実行！git status を打つと今どのリポジトリにいるかがわかります。

トラブル対処（取り消し & 秘密ファイルの保護）
ミスしても大丈夫！Git は最強の消しゴムを持っている

🛡️ 秘密ファイルをGitLabにアップしないために（.gitignore）

パスワード、APIキー、個人情報が書かれたファイルを誤ってGitLabに上げると大事件です。.gitignore にファイル名を書いておくとGitが完全に無視します。

💻 ハンズオン：.gitignore を試す
  1. secret.txt を作りパスワードっぽい文字を書いて保存
  2. .gitignore を作り中に secret.txt と1行書いて保存
  3. git status を実行し、secret.txtが一覧に出ていないことを確認

⏪ 変更前に戻す（git restore）

まだコミットしていない変更を、最後のコミット状態に瞬時に戻します。

# 特定ファイルの変更を取り消す（コミット前）
git restore ファイル名

# git addしたものをカートから取り出す
git restore --staged ファイル名

🕐 コミットを取り消す（git reset）

--softオプションなら、ファイルの中身はそのままでコミットの記録だけ消せます。

# 1つ前のコミットを取り消す（ファイルはそのまま）
git reset --soft HEAD~1

# 過去のセーブデータ一覧を見る（終了はqキー）
git log --oneline

💡 git log --oneline はコンパクトに履歴が確認できます。コミットIDをメモしておくと、さらに昔に戻ることもできます。
